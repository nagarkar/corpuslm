# corpuslm

corpuslm is a library. ytlm and beelm import it. The command line is for checks.

| Ask | Verb |
|---|---|
| What can it do? | `corpuslm help` |
| Is the database healthy? Which schema version is it on? How many rows? | `corpuslm doctor PATH` (add `--json` for machines) |
| Write the review page of every corpus as one file, to look at | `corpuslm review page --config FILE [--out FILE] [--dry-run]` |
| Serve the review page (all corpora, all source kinds) and keep the owner's taps | `corpuslm review serve --config FILE [--port N] [--dry-run]` (launchd runs it; see `scripts/com.nagarkar.corpuslm.review.plist`) |
| Land the saved YouTube answers as verdicts (the Bee ones are beelm's: `./beelm.sh review apply`; this verb leaves them unlanded unless beelm is installed in the same environment) | `corpuslm review apply --config FILE [--kind SOURCE_KIND] [--dry-run]` |
| Keep the AI cleanup's top suggestion for every ambiguity in the database (read from the existing files; no model, no cost) | `corpuslm suggestions record --config FILE [--dry-run]` (safe to run again; the AI cleanup builder records them itself from now on) |
| Fill open review cards with those suggestions for older recordings, for the owner to change on the page | `corpuslm review accept-suggestions --config FILE --kind NAME --before YYYY-MM-DD [--dry-run]` |
| What did the system spend (model dollars by tool, stage and day beside each tool's per-run cap; caption fetches per fetcher and outcome)? | `corpuslm usage show --config FILE [--month YYYY-MM] [--json]`; `corpuslm usage serve --config FILE [--port N] [--dry-run]` serves the same board as the one usage page (launchd: `scripts/com.nagarkar.corpuslm.usage.plist`) |
| Is the review server up and on the newest code? | `corpuslm review check --config FILE` |
| What do the sources claim? Build the claims of some sources by a cheap model call per section (billed; `[claims]` and `[llm]` in `review.toml`; always `--dry-run` first and wait for the owner's yes) | `corpuslm claims build --config FILE [--kind K] [--source ID ...] [--dry-run]` |
| Which sources have current, stale, imported or no claims, and why stale? | `corpuslm claims status --config FILE [--kind K]` (read-only) |
| Bring a manuscript, paper or book in as a text source from a markdown export the owner made (for an authorlm manuscript: `doc create-manuscript` writes `_exports/<Name>.md`; never read a live manuscript) | `corpuslm text import FILE --config FILE --name NAME [--title T] [--dry-run]` (a re-import replaces the paragraphs and leaves the claims stale; the `Perspective sheet` section is left out) |
| Name the concepts the claims use, batch by batch (billed; `[concepts]` in `review.toml`; `--dry-run` first and the owner's yes) | `corpuslm concepts build --config FILE [--kind K] [--source ID ...] [--dry-run]` |
| How many concepts are in, out or on the boundary, the boundary list, the distribution, and which sources' tags are current | `corpuslm concepts status --config FILE [--kind K]` (read-only) |
| The lexicon, or one concept's co-occurrence edges with the shared claim ids | `corpuslm concepts list --config FILE [--state in\|out\|boundary]`; `corpuslm concepts edges LABEL --config FILE` (read-only) |
| Rule a boundary concept in or out (the newest ruling wins over the gate; never overwritten) | `corpuslm concepts verdict LABEL --config FILE --in\|--out` |
| Bring the owner's insight-moment notes in as approved moments (no model; safe to run again) | `corpuslm moments import DIR --config FILE [--dry-run]` |
| Propose moments from claims (billed; `[moments]` in `review.toml`; `--dry-run` first and the owner's yes); approve or decline them on the moments page (`/moments` on the review server) | `corpuslm moments propose --config FILE [--kind K] [--source ID ...] [--dry-run]`; `corpuslm moments status\|list --config FILE`; `corpuslm moments verdict ID --config FILE --approve\|--decline` |
| Name a body of work a monologue may draw on (standing: a text source or a corpus, with a sheet in its own manuscript; occasional: one source) | `corpuslm body add NAME --text ID\|--corpus NAME\|--source ID [--note T] [--manuscript NAME --directory DIR] --config FILE`; `corpuslm body list --config FILE` |
| Draft a standing body's perspective sheet into the `Perspective sheet` tab of its manuscript (billed; `[sheet]`; `--dry-run` first and the owner's yes; the owner rules on the revisions in the Doc), refresh its vocabulary from the concepts in force, or read its version | `corpuslm sheet draft BODY --config FILE [--dry-run]`; `corpuslm sheet refresh BODY --config FILE`; `corpuslm sheet status BODY --config FILE` |
| Make a monologue: name it in its series (an authorlm manuscript, e.g. `SpiritualHindu`, holding its monologues as files `<name>.md`; a series authorlm lacks is registered under the `[claims]` workspace, one it has is found through authorlm, never by listing folders), attach approved moments and bodies of work, see what changed since the last run, run the recipe (billed; `[monologue]`; `--dry-run` first and the owner's yes; the same ingredients never run twice; the monologue file's settled text is the style guide, `--fresh` drops it; a run rewrites that file and the series' `about.md`, one section per monologue) | `corpuslm monologue new NAME --series SERIES [--title T] [--brief T] --config FILE`; `corpuslm monologue attach\|detach NAME --moment ID\|--body NAME --config FILE`; `corpuslm monologue status NAME --config FILE`; `corpuslm monologue run NAME --config FILE [--fresh] [--dry-run]`; `corpuslm monologue list --config FILE` |
| Export the monologue file's settled script for the teleprompter and for podlm (the header names the monologue id and series; by default written beside the file in the series' folder), or read it on the phone at `/teleprompter/<name>` on the review server (tap to scroll) | `corpuslm monologue export NAME [--to FILE] --config FILE` |
| Start a monologue and choose what it draws on from a phone: `/monologues` (start one: a name, its series, a brief) and `/monologues/<name>` on the review server (brief, attached moments and bodies, candidate moments by shared concepts and the brief, bodies from history, videos that fit; Estimate, then Run as the owner's second tap) | `corpuslm review serve --config FILE` names `monologues_url` |
| Turn ytlm's existing digests into claims, no model, no cost | `corpuslm claims import-digests --config FILE [--dry-run]` (safe to run again: a source with claims is left alone) |
| Shell completion | `corpuslm completion` |

- `doctor` is read-only. It never creates, upgrades or writes the file. A missing file, a newer schema or a failed integrity check exits 1 with the reason.
- Run it before and after every migration step. Row counts must match where the step says they should.
- Never query the transcript database with `sqlite3` or raw SQL from another repo. Go through `corpuslm.store.Store`, or ask for a verb.
- The review verbs read `review.toml` (`--config FILE`; example `scripts/review.example.toml`, kept beside the database, never in git). It holds the database path, the port, each kind's folder and the owner's first name; none of them goes on a command line.
- The usage board is the one usage dashboard for the whole system: tools keep no usage page of their own, only their own `usage` verb. It reads `[usage]` of the same `review.toml` (`ledgers`: each tool's ledger folder; `tool_settings`: each tool's own settings file, read only for `[llm].max_usd_per_run` and `max_usd_per_day`), writes nothing and shows counts and money only. Its dollar figures are the tools' own ledger figures; the vendor's meter is the authority.
- The answers table holds only answers not yet landed. `review apply` never calls a model. A kind whose tool must rebuild what an answer changes (Bee: its speaker map, transcript and subtitles) lands only where that tool's rebuilder is registered in this environment (entry-point group `corpuslm.review_rebuilders`, which beelm's package registers); in corpuslm's own venv it is not, so the Bee answers stay unlanded and the board's `left_unlanded` names the verb to run instead: `./beelm.sh review apply`. Always use the tool's own verb for its kind. Word answers wait for the tool's next AI cleanup run (`./beelm.sh corpus ai-cleanup --dry-run` says what it costs). Restart the server after a merge: `launchctl kickstart -k gui/501/com.nagarkar.corpuslm.review` (the owner installs and restarts it).
- `suggestions record` and `review accept-suggestions` call no model. `accept-suggestions` saves answers as the page would (the owner sees them on the page and can change them) and lands nothing; it never overwrites an answer (an undone one included), never touches a speaker card, and leaves a card alone when any of its sources is of another kind, recorded on or after the date (or undated), has no recorded suggestion, or the sources' suggestions differ. The owner chooses `--before`; run `--dry-run` first and never pick a date for them.
- The board shows counts and paths only. Transcript text never enters the chat window, and neither does a claim's text: the claim verbs show counts, states and reasons.
- A claim is a short restatement tied to segments; no table links claims to each other (owner, 2026-10-12). Concepts are derived from claims by recurrence and need no approval above the gate; only the boundary band is put to the owner; edges are co-occurrence counts, never inferred relations (owner, 2026-10-13). A source whose claims are current or imported is never rebuilt by `claims build`; `claims status` names what changed before anything is spent.
- The launcher is `.venv/bin/corpuslm` in this checkout.

## Merging

- Standing authorization (owner, 2026-10-08): this repo has one owner, so the agent merges its own PR once the pre-commit hooks and the test suite pass. It still waits for the owner's word on a PR that changes a rule marked `(owner)` or a metalm guideline, and on one whose first run spends money or migrates live data.
- Revisit trigger: when this repo gets a second contributor, a second user, or runs as a shared service, stop merging on this authorization and ask the owner to update this section.
